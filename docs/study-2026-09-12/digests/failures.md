## Measurement notes and boundaries

1. Middle-round durations lack standalone timestamps in Gemini logs. For round 1, duration is measured from ledger createdAt to the feed terminal event. For the latest round of a lane, duration is measured from ledger roundStartedAt to terminal event. For middle rounds, duration is recorded as unknown with an explicit upper bound set to the span from the prior round terminal event to the current round terminal event.
2. Token accounting uses incremental step_update usage measurements per round. Gemini transcripts accumulate total session usage across resumes in the final result object; summing raw result objects across resumes multiplies counts by up to six times.
3. A completed report does not verify that code was staged, committed, or verified. In retest lanes, lanes wrote structured reports while the QA register validation gate failed on evidence-store dependencies.
4. Only lane r32-mcp round 1 represents an explicit max-runtime failure (hit 45m limit). Malformed function calls on r27-f166 round 1 and hs-r32-sdk round 2 are model empty-call parser rejections, categorized separately.
5. Rounds hs-r35-support round 2 and hs-r35-recompose round 2 succeeded with exit code 0. Their logs contained replayed errors from earlier resumes that the runner ignored, not an automatic retry.
6. Zero rounds failed on quota exhaustion. Stale quota warnings appeared in usage output, but no lane was refused for quota. Zero rounds failed on unanswered questions; all 9 questions submitted through cdx ask received answers from the head.
